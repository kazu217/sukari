# MVP スコープ — PriceLens（仮）

## MVPの定義

「転売業者が実際に使えるかどうか検証できる最小の製品」

課金・全機能は不要。**バーコードをスキャンして Amazon + 楽天の価格が出れば価値を検証できる。**

---

## MVP に含めるもの（IN）

### 画面構成（最小5画面）

```
1. ホーム / スキャン画面（メイン）
2. 検索結果 / 価格一覧画面
3. 利益計算モーダル（仕入れ値入力 → 利益表示）
4. スキャン履歴画面
5. 設定画面（プラン確認・ログイン）
```

### 機能

| 機能 | 優先度 | 実装方針 |
|------|--------|---------|
| バーコード・QRスキャン | 必須 | Expo Barcode Scanner |
| Amazon価格取得 | 必須 | PA-API v5 |
| 楽天価格取得 | 必須 | 楽天商品検索API |
| テキスト手動検索 | 必須 | PA-API + 楽天API |
| 利益計算（仕入れ値入力） | 必須 | クライアント側で計算 |
| スキャン履歴（直近20件） | 必須 | Supabase |
| メールログイン | 必須 | Supabase Auth |
| 各サイトへのリンク（アフィリエイト付き） | 必須 | ディープリンク |

---

## MVP から外すもの（OUT）

| 機能 | 除外理由 | いつ追加するか |
|------|---------|-------------|
| AI画像認識 | Google Vision APIの設定コストが高い | v1.1 |
| メルカリ価格 | スクレイピングの法的検討が必要 | v1.1 |
| ヤフオク価格 | 同上 | v1.1 |
| 月額課金 | 先に価値検証してから | v1.1 |
| 価格アラート | 複雑 | v1.2 |
| 価格履歴グラフ | Keepa連携が必要 | v1.2 |
| CSV出力 | ニーズ検証が必要 | v1.2 |
| Apple / Googleソーシャルログイン | 後から追加可能 | v1.1 |

## 開発工程（MVP: 推定6〜8週間）

### Week 1-2: 基盤構築
- [ ] Expo プロジェクト初期化（React Native + TypeScript）
- [ ] Supabase プロジェクト作成・テーブル設計
- [ ] Amazon PA-API 接続テスト（Supabase Edge Function）
- [ ] 楽天API 接続テスト

### Week 3-4: コア機能実装
- [ ] バーコードスキャン画面
- [ ] 価格一覧表示画面
- [ ] 利益計算モーダル
- [ ] Supabase Auth（メールログイン）

### Week 5: UX改善 + ヒストリー
- [ ] スキャン履歴保存・表示
- [ ] ローディング・エラー状態のUI
- [ ] キャッシュ実装（同じ商品を15分以内に再検索した場合）

- [ ] 実機テスト（iPhone + Android）
- [ ] App Store Connect / Google Play Console 登録
- [ ] TestFlight ベータ配布（身近な転売業者 10〜20人）
- [ ] App Store 審査申請

## MVP成功基準

TestFlight配布後2週間以内に:

| 指標 | 合格基準 |
|------|---------|
| テスター継続利用率 | 2週間後も50%以上が使っている |
| スキャン/人/日 | 平均10回以上 |
| 「有料でも使う」アンケート | 50%以上がYes |
| 致命的バグ | 0件 |

→ **全て合格したら v1.1（課金・AI認識・フリマ価格）の開発を開始する。**

## テスト計画

## リスク管理

| リスク | 対策 |
|-------|------|
| Amazon PA-APIの申請が通らない | 申請はプロジェクト開始直後に行う。代替としてスクレイピングを検討 |
| 楽天APIのデータが不正確 | 複数ショップの最安値を表示し、ユーザーが判断できるようにする |
| App Store審査リジェクト | アフィリエイトリンクの扱いをガイドラインに沿って実装 |
| バーコード認識精度が低い | expo-barcode-scannerは精度高い。万全を期すなら Vision APIのバーコード検出も併用 |
